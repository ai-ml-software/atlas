Mobile installation and connection / تثبيت التطبيق والاتصال

The current signed Android build is ALTUS 1.0.1, version code 2, ARM64. It connects to this local Laragon installation using http://localhost/atlas/atlas. The build contains an app configuration key only; it contains no user's personal sign-in key. Production deployment and app-store submission are separate.

1. Prepare the backend

Keep Laragon Apache and MySQL running. Follow backend installation, use the local database override and run additive migrations through 31. Open http://localhost/atlas/atlas/hkp/admin/mobile as a system administrator; confirm Mobile app settings appears in Platform and the legacy admin sidebar. Existing accounts, certificates and learner history are preserved.

From the repository root, the local setup helper can create the ignored mobile .env and an app configuration key through the native service:


& 'C:\laragon\bin\php\php-8.1.10-Win32-vs16-x64\php.exe' index.php mobile_cli configure_local

& 'C:\laragon\bin\php\php-8.1.10-Win32-vs16-x64\php.exe' index.php mobile_cli configure_preview

The helper refuses a remote database/URL and does not replace an existing .env. configure_preview enables only localhost/127.0.0.1 port 8083 in the ignored application/config/ha_mobile.local.php. Hosted previews should use exact HTTPS origins through HA_MOBILE_WEB_ORIGINS. Native apps do not depend on browser CORS.

2. Install on an Android phone or emulator

Install Android platform-tools. Connect an authorised ARM64 phone by USB, enable USB debugging and accept its computer prompt. The local computer must keep Apache running. In a new PowerShell window:


adb devices

adb reverse tcp:80 tcp:80

adb install -r 'C:\laragon\www\atlas\atlas\mobile app\client-deliverables\android\ALTUS-1.0.1-release.apk'

Reverse forwarding makes the phone's localhost:80 reach Laragon on the computer. Repeat it after disconnecting or restarting the device. On an Android emulator you can instead configure http://10.0.2.2/atlas/atlas and the matching app key in Server setup. The default APK is ARM64; build with the emulator's matching architecture if needed. A standalone phone without USB forwarding needs a reachable deployed HTTPS server. Do not enter the computer's localhost address and expect it to work over Wi-Fi.

Open the app. In Sign in or Profile → Settings, choose Server setup. Verify the URL and key prefix, then Test connection. If using a replacement key, enter the new altm_… value and Save. Settings contains a visible Personal API key option as well.

3. Sign in as admin, student or instructor

On Sign in, choose Get my personal API key. Sign in to the website and open Account Security. Enter your current password and authenticator code if enabled, then Create personal mobile key. Copy the ha_… key once and paste it into the app's Personal API key field with the same platform URL. Press Connect account. The key follows the user's live roles, permissions and tenant access and expires after 90 days. Revoke it from Account Security when replacing a device. Learners need no general integration-key permission for this own mobile key.

4. Build from source


cd 'C:\laragon\www\atlas\atlas\mobile app\altus-mobile'

npm.cmd ci

Copy-Item '.env.example' '.env' # Only for a new setup; do not replace an existing configured file.

# Edit .env with the reachable URL and the altm_ key from the same backend.

npm.cmd run check

npx.cmd expo start --clear

The required environment values are:


EXPO_PUBLIC_PLATFORM_URL=http://localhost/atlas/atlas

EXPO_PUBLIC_ALTUS_APP_KEY=altm_<key-from-this-backend>

.env is ignored by Git. Public Expo variables are compiled into the JavaScript bundle, so never put ha_ keys, AI credentials or signing passwords there. A changed .env requires restarting Expo or rebuilding the APK. A saved device Server setup takes precedence until reset.

For a signed Windows build, the existing wrapper stages generated Android code in a separate short directory and reuses the private signing key:


powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-android-windows.ps1

Its output name follows app.json's version. Increase Android versionCode for subsequent releases. The network config plugin allows plain HTTP only for localhost, 127.0.0.1 and 10.0.2.2; all other hosts require HTTPS. Do not remove this policy to work around a production TLS problem.

5. Browser preview and tests


npm.cmd run export:web

node scripts/serve.cjs

# Open http://127.0.0.1:8083

From the repository root, run the PHP regression suite only in its protected test namespace:


$env:HA_TEST_DB='atlas_hospitality_test_mobile_fix'

& 'C:\laragon\bin\php\php-8.1.10-Win32-vs16-x64\php.exe' index.php ha_test run

For browser fixtures, prepare the dedicated atlas_hospitality_test database before the first run; this rebuilds that test database only. In e2e, run npx.cmd playwright test --config=playwright.studio.config.ts tests/mobile-settings.spec.ts --project=desktop. The exported mobile preview must already be running on port 8083. These tests cover menu/tenant restrictions, Arabic/mobile layout, configuration/key lifecycle, actual Expo setup, own learner key creation and actual live sign-in. The role-video recording script also checks every recorded page for HTTP/PHP errors.

Production and iOS

Deploy the backend changes first, run migrations and generate the production site's own app key. Configure EXPO_PUBLIC_PLATFORM_URL=https://altusgulf.com only when that site's mobile endpoints and credentials are ready. A key generated in the local database does not authenticate on another database. Follow the existing mobile release guide for signing, EAS and store steps. Do not upload the local .env, test accounts or local API keys as production credentials. iOS needs a Mac or authorised EAS build and device/TestFlight validation; it was not built on this Windows host.

العربية

شغّل Apache وMySQL وثبّت ترحيلات قاعدة البيانات حتى الإصدار 31. افتح إعدادات تطبيق الجوال بحساب مسؤول النظام وأنشئ مفتاح altm_ عند الحاجة. للتجربة المحلية على هاتف USB استخدم adb reverse tcp:80 tcp:80 ثم ثبّت ملف APK إصدار 1.0.1. اختبر الاتصال من إعداد الخادم واحفظ. أنشئ مفتاحك الشخصي ha_ من أمان الحساب بعد تأكيد كلمة المرور والمصادقة الثنائية، ثم استخدمه في ربط الحساب. للإنتاج استخدم خادم HTTPS ومفتاحًا صادرًا من قاعدة بيانات الإنتاج نفسها. لا تضع المفاتيح الشخصية في .env.
